# Лендинг + Telegram-бот для шиномонтажа (Яхрома) — план реализации

> Для исполнения: используй скилл execute-plan, задача за задачей. Шаги — чекбоксы (`- [ ]`) для отслеживания.

**Цель:** Рабочий демо-лендинг шиномонтажа (Вокзальная 75, Яхрома) с формой бронирования, которая реально долетает Алексу в Telegram через отдельного бота, плюс публичная ссылка, которую можно показать владельцам.

**Подход:** Статический одностраничный лендинг (HTML/CSS/vanilla JS, без фреймворков) + отдельный Node.js-бот (grammy + встроенный http-сервер) как бэкенд для приёма заявок. Бот хранит токен и шлёт заявки Алексу. Сайт деплоится на этом же сервере через Caddy на поддомене sslip.io, бот — через systemd.

**Стек:** HTML/CSS/JS (без сборщиков), Node.js + grammy (бот), встроенный `node:http` (без Express — задача маленькая, лишняя зависимость не нужна).

**Концепция:** `~/projects/yahroma-tire/knowledge/concept.md`

## Общие ограничения

- Реальные данные бизнеса (не выдумывать): Вокзальная ул. 75, Яхрома; тел. +7 (916) 169-06-26; круглосуточно; рейтинг 5,0 из 66 отзывов; демонтаж/монтаж 250₽; заплатка на камеру 500₽
- Слоты бронирования — 2-часовые окна на 24 часа, НЕ привязаны к реальной занятости мастеров (концепция, не-цели)
- Скидки/бонусы на лендинге помечены как демо-пример (концепция: не согласовано с владельцами)
- Токен Telegram-бота никогда не попадает в клиентский JS — только на сервере бота
- Мобильная адаптивность — приоритет (концепция: анти-цели)
- Деплой: systemd-сервис для бота (не nohup/&), Caddy + поддомен sslip.io для сайта — по правилам сервера в CLAUDE-SYSTEM.md

## Фокус ревью

- Токен бота случайно зашит в `site/script.js` или любой публично отдаваемый файл — проверить grep по билду перед деплоем
- Телефон в форме принимает произвольный мусор (буквы, пустую строку) — должна быть минимальная проверка на фронте и бэке
- Двойной сабмит формы (двойной клик) создаёт две заявки Алексу — кнопка должна блокироваться после отправки
- Сайт и бот на разных портах/происхождениях — без CORS-заголовка на бот-эндпоинте форма не отправится из браузера
- На узких экранах (320-375px, самые частые телефоны) календарь слотов или футер с телефоном вылезают за экран / текст нечитаем

## Задача 1: Структура проекта и бот-сервер (скелет)

**Файлы:**
- Создать: `~/projects/yahroma-tire/.gitignore`

- Создать: `~/projects/yahroma-tire/bot/.env.example`
- Создать: `~/projects/yahroma-tire/bot/bot.js`

**Интерфейсы:**
- Отдаёт: HTTP-сервер на порту из `process.env.PORT` (по умолчанию 3300), эндпоинт `POST /api/booking`, пока просто возвращает `200 {"ok":true}` без логики — логика добавится в задаче 5.

- [ ] **Шаг 1: Создать `.gitignore`** — строки `node_modules/`, `.env`, `*.log`
- [ ] **Шаг 2: Создать `bot/package.json`** — имя `yahroma-tire-bot`, зависимость `grammy` (последняя стабильная), `type: module`, script `start: node bot.js`
- [ ] **Шаг 3: Создать `bot/.env.example`** с плейсхолдерами `BOT_TOKEN=`, `ADMIN_CHAT_ID=`, `PORT=3300`
- [ ] **Шаг 4: Написать `bot/bot.js`** — поднимает `node:http` сервер на `PORT`, маршрут `POST /api/booking` отвечает `200 {"ok":true}` (заглушка), любой другой маршрут — 404. Настроить CORS-заголовок `Access-Control-Allow-Origin: *` на ответах `/api/booking` (включая `OPTIONS` preflight)
- [ ] **Шаг 5: Проверка** — `cd bot && npm install && node bot.js`, в соседнем терминале `curl -X POST http://localhost:3300/api/booking` → ожидается `{"ok":true}`. Остановить процесс (Ctrl+C)
- [ ] **Шаг 6: Закоммитить** — `git add bot/ .gitignore && git commit -m "feat: скелет бот-сервера для приёма заявок"`

## Задача 4: JS — генератор слотов и отправка формы

**Файлы:**
- Создать: `~/projects/yahroma-tire/site/script.js`

**Интерфейсы:**
- Использует: `#slots`, `#booking-form`, `#booking-status` из Задачи 2
- Отдаёт: функция `generateSlots(date: Date) -> Array<{label: string, value: string}>` — 2-часовые окна на 24 часа от текущего момента; обработчик `submit` формы, который шлёt `fetch('/api/booking', {method: 'POST', body: JSON...})` на тот же origin, что и сайт (относительный путь — задача 8 настроит прокси, чтобы `/api/booking` указывал на бот-сервер)

- [ ] **Шаг 1: Написать `generateSlots(date)`** — возвращает слоты от ближайшего круглого 2-часового окна вперёд на 24 часа (12 слотов), прошедшие часы сегодняшнего дня не включать
- [ ] **Шаг 2: Отрисовать слоты в `#slots`** — кнопки/чипы по одной на слот, клик помечает выбранным (убирает выделение с остальных) и записывает значение в скрытое поле `slot`
- [ ] **Шаг 3: Валидация телефона** — простая проверка на стороне клиента: минимум 10 цифр после удаления всех нецифровых символов; при ошибке — текст в `#booking-status`, не отправлять
- [ ] **Шаг 4: Обработчик отправки** — при валидной форме: отключить кнопку отправки (защита от двойного сабмита), `fetch('/api/booking', {method:'POST', headers:{'Content-Type':'application/json'}, body: JSON.stringify({phone, slot, fallback_time})})`, при успехе — показать сообщение "Заявка отправлена, вам перезвонят", при ошибке сети — текст с просьбой позвонить напрямую + номер телефона, кнопку разблокировать
- [ ] **Шаг 5: Проверка** — открыть `index.html` через локальный `python3 -m http.server` (не `file://`, иначе fetch не отработает корректно), в DevTools Network посмотреть, что при сабмите уходит POST-запрос с правильным телом (бот ещё не слушает на этом порту — ошибка сети ожидаема и должна красиво отрабатываться)

## Задача 5: Бот — приём заявки и пересылка Алексу

**Файлы:**
- Изменить: `~/projects/yahroma-tire/bot/bot.js`

**Интерфейсы:**
- Использует: заглушку `/api/booking` из Задачи 1
- Отдаёт: реальная логика — парсит JSON-тело, валидирует `phone` непустой, инициализирует `grammy Bot` с `process.env.BOT_TOKEN`, при валидной заявке шлёт `process.env.ADMIN_CHAT_ID` сообщение с телефоном/слотом/fallback-временем, отвечает клиенту `200 {"ok":true}`; при невалидном теле — `400 {"ok":false,"error":"..."}`

- [ ] **Шаг 1: Парсинг JSON-тела запроса** — собрать тело из потока, `JSON.parse`, обработать ошибку парсинга (`400` при битом JSON)
- [ ] **Шаг 2: Валидация** — `phone` обязателен и непустой после трима; `slot` и `fallback_time` опциональны, но хотя бы одно из двух должно быть заполнено (иначе непонятно, когда клиент ждёт)
- [ ] **Шаг 3: Инициализация grammy Bot** — `new Bot(process.env.BOT_TOKEN)`, если токена нет в `.env` — процесс падает с понятной ошибкой при старте, не молча
- [ ] **Шаг 4: Отправка сообщения Алексу** — `bot.api.sendMessage(process.env.ADMIN_CHAT_ID, текст)`, текст включает телефон, выбранный слот или fallback-время, таймстамп заявки
- [ ] **Шаг 5: Ответ клиенту** — `200 {"ok":true}` при успешной отправке, `502 {"ok":false}` если `sendMessage` упал (но не ронять процесс)
- [ ] **Шаг 6: Проверка** — создать реальный `.env` из `.env.example` с тестовым ботом (или попросить у Алекса BOT_TOKEN/ADMIN_CHAT_ID для этого проекта, см. примечание ниже), `node bot.js`, `curl -X POST http://localhost:3300/api/booking -H "Content-Type: application/json" -d '{"phone":"+79161234567","slot":"14:00-16:00"}'`, убедиться что сообщение реально пришло в Telegram
- [ ] **Шаг 7: Закоммитить**

> **Примечание на этапе исполнения:** для этой задачи нужен реальный токен Telegram-бота — Алекс создаёт его через @BotFather и даёт мне токен + свой chat_id (или сам заполняет `.env` на сервере). Без этого шаг 6 нельзя реально проверить, только проверить, что код не падает на синтаксисе.
